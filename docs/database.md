# Database

`Database` is the iPod's music database (`iPod_Control/iTunes/iTunesDB`): tracks, playlists,
the album and artist lists and, through the artwork manager, the cover art in the ArtworkDB.
Open it on a mount point, change it, `save()`. Nothing is written before `save()`.

```python
import pygpod

db = pygpod.Database(mountpoint)
track = db.add_track(song, title="Без бою", artist="Океан Ельзи", album="Земля", year=2013)
db.set_playlist("Обране", [track])
db.save()

db = pygpod.Database(mountpoint)
assert [t.title for t in db.get_playlist("Обране").tracks] == ["Без бою"]
print(db.summary())
```

The context manager saves on a clean exit (and only if something changed):

```python
with pygpod.Database(mountpoint) as db:
    db.tracks[0].rating = 80
assert pygpod.Database(mountpoint).tracks[0].rating == 80
```

## Opening

- `Database(mountpoint)` reads the iTunesDB, the device information (see [device.md](device.md))
  and the play counts the iPod recorded since the last sync, which are merged into the tracks
  unless `apply_play_counts=False` (see [playcounts.md](playcounts.md)).
- It also completes or discards a save that was interrupted (power loss, unplugged cable);
  `recover=False` opens without touching any file, e.g. for a read-only check.
- `Database.from_file(path)` parses a standalone iTunesDB file; `save_to_file(path)` writes one.

## Tracks and playlists

`add_track()` copies a file to `iPod_Control/Music/Fxx` (or references a file already there with
`copy=False`), reads its tags and checks that the model plays it (`convert=True` converts what it
cannot, see [media.md](media.md)). Keyword arguments set any field and always win over the tags.
`remove_track()` / `remove_tracks()` remove tracks from the database and every playlist (and their
files with `delete_file(s)=True`). Playlists: `create_playlist()`, `set_playlist()`,
`get_playlist()`, `add_track_to_playlist()`, `delete_playlist()`; smart playlists in
[playlists.md](playlists.md).

## Saving

- **Crash-safe**: the iTunesDB, ArtworkDB, .ithmb files and the iTunesSD are committed together
  through a journal (`iPod_Control/iTunes/pygpod.journal`); either the old or the new database is
  on the iPod, never a mix.
- **One writer at a time**: `save()` holds `iPod_Control/iTunes/pygpod.lock` and raises
  `ConflictError` when another program saved the database since this object loaded it
  (`save(force=True)` overwrites).
- **Signed like the model needs it**: hash58 for the Classic and nano 3G/4G (with the iPod's
  FirewireGuid), hash72 with `iPod_Control/Device/HashInfo`, nothing for older models, like
  libgpod. The checksum inputs are checked before anything is written (`HashError`).
- **Library indexes**: the sort indexes and letter jump tables the iPod browses and quick-scrolls
  by, and the album and artist lists, are rebuilt when the tracks they depend on changed, with
  libgpod's rules (sort fields, "The X" as "X, The", jump letter = first letter or digit); an
  unchanged save keeps them, so a database written by iTunes or libgpod stays byte-identical.
- Live smart playlists are refreshed, On-The-Go playlists handled per
  `DatabaseConfig.otg_on_save` (see [playcounts.md](playcounts.md)), the shuffle's iTunesSD
  rewritten.

## Timestamps

Track times (added, modified, played, skipped, released), playlist and photo dates are stored on
the iPod as its local wall time, as iTunes and libgpod do. pygpod converts them with the timezone
set on the iPod (`iPod_Control/Device/Preferences`), else with the computer's current UTC offset
(`db.timezone_shift`, seconds east of UTC). The `datetime` values pygpod returns are aware (UTC).
Dates outside the iPod's range (1904-01-01 to 2040-02-06) are clamped to its ends with a warning.
`DatabaseConfig(timestamps="utc")` reads and writes them as UTC instead (pygpod 0.1.0's
behaviour).

## Configuration

`DatabaseConfig` controls a few behaviours and the binary output (libgpod-compatible by default):

```python
config = pygpod.DatabaseConfig(otg_on_save="keep", random_seed=1)
db = pygpod.Database(mountpoint, config=config)
assert db.config.otg_on_save == "keep"
```

### `pygpod.Database`

`Database(mountpoint: 'Optional[str]' = None, config: 'Optional[DatabaseConfig]' = None, apply_play_counts: 'bool' = True, recover: 'bool' = True) -> 'None'`

```text
High-level iPod database API.

Provides Pythonic access to tracks, playlists, and device info.

Usage:
    db = Database("/mnt/ipod")
    for track in db.tracks:
        print(f"{track.artist} - {track.title}")

    db.add_track("/path/to/song.mp3")
    db.save()

Play counts: the iPod records plays, skips, ratings and bookmarks since the
last sync in a separate file (Play Counts / iTunesStats / PlayCounts.plist).
With ``apply_play_counts=True`` (default) they are merged into the tracks on
open; with ``False`` they are only read, see pending_play_counts(),
merge_play_counts() and clear_play_counts(). The file is deleted only after
the next successful save(), so a session that does not save loses nothing.

Opening completes or discards an interrupted save (``recover=True``, default).
``recover=False`` opens read-only-style without touching any file (used by check());
save() then refuses while the journal of an interrupted save is still there.
```

#### `Database.add_track(self, filepath: 'str', copy: 'bool' = True, convert: 'bool' = False, *, video_size: 'str' = 'small', **kwargs: 'Any') -> 'Track'`

```text
Add a track to the iPod.

If mutagen is installed, tags are read automatically from the file.
Additional/override metadata can be passed as keyword arguments and
always wins over the file's tags.

Args:
    filepath: Path to the audio file to add.
    copy: Copy the file to iPod_Control/Music/Fxx (default). False: the
        file is already on the iPod (must be inside the mount point's
        iPod_Control/Music) and is referenced in place.
    convert: Convert audio this iPod cannot play (FLAC, Ogg, Opus, WMA,
        > 48 kHz, > 2 channels ...) with ffmpeg instead of refusing it:
        lossless sources become Apple Lossless where the iPod plays it,
        everything else AAC (see pygpod.convert). Tags and artwork come
        from the original file. Needs copy=True. Video (on iPods that play
        it) that does not fit the iPod's H.264 profile (checked with
        ffprobe) becomes an .m4v with H.264 Baseline + AAC; video that fits
        is copied unchanged.
    video_size: Target of video conversion: "small" (inside 320x240,
        plays on every video iPod, default) or "large" (inside 640x480
        where the model plays it: 5.5G, nano 3G-5G, Classic).
    **kwargs: Metadata overrides: title, artist, album, albumartist
        (alias album_artist), genre, composer, comment, grouping, year,
        track_number, total_tracks, cd_number, total_cds, compilation,
        media_type, category, description, podcast_url, podcast_rss,
        rating (0-100), bpm, explicit_flag (1 explicit, 2 clean),
        time_released (datetime), sort_title, sort_artist, sort_album,
        sort_albumartist, sort_composer, sort_tvshow, keywords,
        play_count, skip_count, bookmark_time (ms),
        time_played (datetime), remember_position, skip_when_shuffling,
        mark_unplayed, soundcheck (MHIT value; default from the file's
        iTunNORM / ReplayGain tags, see tags.read_soundcheck; 'analyze'
        measures the audio with ffmpeg (the converted file with convert=True),
        'auto' measures only files without gain tags), pregap,
        postgap, sample_count, gapless_data, gapless_track_flag,
        gapless_album_flag (default from the LAME tag / iTunSMPB, see
        pygpod.gapless); gapless='estimate' (or 'auto') estimates them for
        MP3s without a LAME/Info tag and AAC without iTunSMPB or edit list
        (experimental, see pygpod.gapless.estimate_gapless), gapless={...}
        sets them,
        chapters (list of (start_ms, title) tuples or a ChapterData;
        default from the file: MP4 chapter track / Nero chpl, ID3 CHAP,
        see pygpod.chapters.read_chapters; [] = no chapters),
        cover_art (image path or bytes); for videos also
        tvshow, tvepisode, tvnetwork, season_number, episode_number.
        A video file (an MP4 with a video track) added without
        media_type becomes MEDIATYPE_VIDEO, or MUSICVIDEO/TVSHOW from its
        iTunes media kind atom; video tracks get movie_flag set.

Returns:
    The new Track object.

Raises:
    TrackError: If the file doesn't exist or can't be processed.
```

#### `Database.save(self, refresh_smart_playlists: 'bool' = True, force: 'bool' = False) -> 'None'`

```text
Save the database back to the iPod.

Live-updating smart playlists are refreshed first (like libgpod's itdb_write,
which calls itdb_spl_update_live); pass ``refresh_smart_playlists=False`` to keep
their stored members. Non-live smart playlists and normal playlists are never touched.

Concurrency: the save holds ``iPod_Control/iTunes/pygpod.lock`` (see db/writelock.py) and
raises ConflictError when the iTunesDB on the iPod is no longer the one this object loaded
or last saved (another writer saved meanwhile) - reopen and redo the changes, or pass
``force=True`` to overwrite.

Crash-safe: checksum inputs are validated before anything is written,
then iTunesDB, ArtworkDB and compacted .ithmb files are committed
together (see db/transaction.py). On any failure nothing is replaced
and the exception propagates.
```

### `pygpod.DatabaseConfig`

`DatabaseConfig(string_encoding: 'int' = 1, mhod_order: 'Optional[Tuple[int, ...]]' = (1, 4, 3, 6, 2, 5), unk_0x7e: 'int' = 65535, unk_0x84: 'int' = 0, unk_0x90: 'int' = 12, mark_unplayed: 'int' = 1, unk_0x12c_from_filesize: 'bool' = True, unk_0x134_fill: 'int' = 128, unk_0x168: 'int' = 1, set_time_fields_zero: 'bool' = False, timestamps: 'str' = 'local', mhyp_unk_0x28: 'int' = 1, mhyp_sort_order: 'int' = 1, generate_album_list: 'bool' = True, generate_artist_list: 'bool' = True, chapter_format: 'str' = 'atom', spl_prefs_padded_size: 'int' = 72, master_playlist_name: 'str' = 'iPod', platform: 'int' = 1, language: 'int' = 25966, filename_prefix: 'str' = 'pygpod', filename_rand_len: 'int' = 6, filename_charset: 'str' = 'digits', track_id_start: 'int' = 52, random_seed: 'Optional[int]' = None, otg_on_save: 'str' = 'import') -> None`

```text
Configuration for iPod database generation.

Defaults match libgpod for maximum device compatibility. The fields most callers change:

- ``otg_on_save``: what save() does with On-The-Go playlists made on the iPod:
  "import" (default, like iTunes and libgpod: playlists "OTG Playlist n", files removed),
  "keep" (files kept, positions rewritten) or "clear" (files removed).
- ``timestamps``: "local" (default, the iPod's local time like iTunes and libgpod) or
  "utc" (pygpod 0.1.0's behaviour).
- ``random_seed``: an int makes database/track/playlist ids and file names reproducible.
- ``master_playlist_name``: name of the library playlist in a new database ("iPod").
- ``set_time_fields_zero``: leave time_added/time_modified of new tracks 0 instead of now.

The other fields are header values of the binary format, set to what libgpod writes.
```
