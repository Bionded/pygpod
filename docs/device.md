# Device, models, initialising an iPod

`Device` describes the iPod behind a mount point: model and generation, checksum scheme,
FirewireGuid, cover-art and photo formats, capabilities (video, artwork, podcasts) and
storage use. `Database(mountpoint).device` is the same object.

Where the information comes from, in this order (as libgpod does):

1. `iPod_Control/Device/SysInfoExtended` (an XML plist the firmware provides; libgpod and
   iTunes copy it to the iPod): the database version that decides the checksum scheme, the
   FirewireGuid and the exact cover-art (`AlbumArt`) and photo (`ImageSpecifications`) formats;
2. `iPod_Control/Device/SysInfo`: `ModelNumStr` (the model table) and `FirewireGuid`;
3. USB (the `usb` extra), only for the iPod behind this mount point: model and FirewireGuid when
   the files lack them.

An iPod none of these identify keeps working: `checksum_known` is False and `save()` signs the new
database like the one already on the iPod (or raises `HashError` when that needs a GUID it does
not have).

```python
import pygpod

device = pygpod.Device.from_mountpoint(mountpoint)
print(device.model, device.generation.name, device.checksum_type.name, device.firewire_guid)
assert device.supports_video and device.requires_hash and device.checksum_known
print([f.format_id for f in device.get_cover_art_formats()])
print(device.storage_info(full=False))
```

| checksum (`checksum_type`) | models | needs |
|---|---|---|
| `NONE` | 1G-4G, Photo, mini, Video 5G/5.5G, nano 1G/2G, shuffles | - |
| `HASH58` | nano 3G/4G, Classic | FirewireGuid |
| `HASH72` | nano 5G (database not supported, see the README) | `iPod_Control/Device/HashInfo` |
| `HASHAB` | nano 6G | not supported: `save()` raises `HashError` |

## Initialising an iPod

`init_ipod()` creates the folder structure (`iPod_Control/iTunes`, `Music/F00`..., `Artwork`,
`Device`) and an empty database signed for the model; it never formats or partitions anything.
`reset=True` starts from zero: it deletes `iPod_Control/iTunes` (including iTunes' `IC-Info.sidb`),
`Artwork` and `Music` and keeps the SysInfo files unless `keep_sysinfo=False`. `sysinfo_files`
writes SysInfo/SysInfoExtended (e.g. on an emulated volume), `dry_run=True` only lists the actions.

```python
import os

fresh = f"{workdir}/fresh"
os.makedirs(fresh)
actions = pygpod.init_ipod(fresh, name="Новий iPod", dry_run=True)  # plan only
pygpod.init_ipod(fresh, name="Новий iPod")
assert pygpod.validate_mountpoint(fresh)
assert pygpod.Database(fresh).master_playlist.name == "Новий iPod"
```

`discover()` looks at mounted volumes and USB devices (needs a real iPod):

```py
for mountpoint, device in pygpod.discover():
    print(device.model, mountpoint)
```

#### `Device.from_mountpoint(cls, mountpoint: 'str') -> 'Device'`

```text
Create a Device by reading info from an iPod mount point.

Autodetection priority:
1. ModelNumStr from SysInfo → direct model number lookup
2. Serial number from SysInfoExtended → 3-char suffix lookup
   (libgpod checks serial first, but model number is more precise
   when present; both yield the same result for valid iPods)
3. USB device detection (serial lookup, then product ID lookup)
4. Unknown device (still usable with limited capabilities)

Args:
    mountpoint: Path to the iPod mount point.

Returns:
    Device instance with detected model and capabilities.
```

### `pygpod.init_ipod(mountpoint: 'str', model: 'str' = 'classic_6g', music_dirs: 'int' = 50, *, name: 'str' = 'iPod', reset: 'bool' = False, keep_sysinfo: 'bool' = True, sysinfo_files: 'Optional[Dict[str, bytes]]' = None, artworkdb: 'bool' = True, dry_run: 'bool' = False) -> 'List[InitAction]'`

```text
Initialize an iPod directory structure with an empty iTunesDB.

Creates all necessary directories and writes a minimal iTunesDB
containing only a master playlist named ``name`` (the device name shown
by the iPod and iTunes), plus an empty ArtworkDB. Like libgpod, the new
iTunesDB is signed for the device in the SysInfo files (hash58 with the
FirewireGuid, hash72 with HashInfo); without them it stays unsigned until
the first save().

Never formats or partitions anything: to start from a fresh filesystem the
caller formats the data partition first and passes the SysInfo files read
before formatting (see read_sysinfo_files()).

Args:
    mountpoint: Path to the iPod mount root.
    model: iPod model identifier (kept for compatibility, unused).
    music_dirs: Number of Fxx music directories to create.
    name: Device name (master playlist name) for a newly written iTunesDB.
    reset: Start from zero: delete iPod_Control/iTunes, Artwork and Music
        contents (tracks, databases, play counts, also iTunes' IC-Info.sidb)
        and write a new empty database. iPod_Control/Device is kept (SysInfo files subject to
        ``keep_sysinfo``). Without ``reset`` an existing iTunesDB is kept.
    keep_sysinfo: Keep existing SysInfo/SysInfoExtended (with ``reset``);
        False deletes them.
    sysinfo_files: SysInfo file contents to (re)write, e.g. read before a
        format. Written as given, overriding existing files.
    artworkdb: Also write an empty ArtworkDB when none exists (or on reset).
    dry_run: Only report what would be done; nothing is touched.

Returns:
    The actions performed (or planned, with ``dry_run``), in order.

Raises:
    MountPointError: If the mountpoint doesn't exist.
```
